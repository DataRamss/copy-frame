# Better Writer

## Overview

先判断文体，再按成熟编辑稿的标准改写：开头不空转，判断先于姿态，信息密度高但不堆术语，句子干净，少广告腔、少自媒体夸张腔、少 AI 总结腔。
默认直接给成稿。只有用户明确要求时，才补修改说明、对比版或多版本分支。

## Quick Decision Tree

先判断输入属于哪一类，再调用对应规则：

- 科技媒体稿 / 评论稿 / 资讯深写：优先强化开头、结构推进、判断句、信息密度。
- 口播稿：优先保证顺口、停顿、节奏、易懂，再补判断和质感。
- 社媒文案：优先压缩句子、提纯观点、提高抓人能力，避免堆感叹和钩子套话。
- 品牌稿 / 产品稿：优先保留业务目标和卖点，但把硬广味、空词和自夸姿态收掉。

如果用户没有说明文体，就根据长度、语气、用途判断；判断不准时，按“改稿优先、保真优先、少写空话”处理。

## Rewrite Workflow

按下面这条编辑梯子工作，不要跳步：

1. 事实与观点保真
- 先锁住用户原文里的事实、数据、结论、立场、对象和用途。
- 不新增用户没有提供的事实、采访、案例、数据、时间线。
- 不为了“更像媒体”改掉原文真正想表达的意思。

2. 去模板感
- 先删空泛铺垫、课程腔、客服腔、营销套话、AI 总结腔。
- 先删重复句、解释姿态、模板转折，再做重写。
- 遇到对比关系，不要落回“不是 X，而是 Y”这类对举模板。优先改成两句直说：先落主判断，再补次要项为什么不关键。
- 默认把“看的不是”“重点不是”“关键不是”“真正不是”都视作同一种模板，不要换壳复活。

3. 重建开头
- 开头优先落具体信息、冲突、场景、判断或关键变化。
- 不要用“大多数人不知道的是”“在当下这个时代”“从某种意义上来说”这种空转开头。
- 用户给的信息不够时，宁可开门见山，也不要脑补故事。

4. 提升信息密度
- 用细节承接观点，用动作替代抽象名词。
- 能一句说完的，不拆成三句解释姿态；该拆开的长句再拆。
- 同一层意思只说一次，不要换三种说法连着讲。

5. 增加判断感
- 该下判断时直接下判断，不先摆姿态再说重点。
- 判断要落在用户已给出的信息和语境上，不要凭空拔高。
- 锋利可以保留，但不要靠夸张词、狠话、反问句硬撑。

6. 调整节奏与收尾
- 让段落往前推，而不是原地解释。
- 收尾要么落判断，要么落动作，要么落结果，不要再包一层总结。
- 信息少时先收敛表达，不补设定；营销味重时先保留卖点，再删空词。

## Format Adapters

### 科技媒体稿 / 评论稿

- 开头尽快进入信息点、产品变化、行业含义或核心判断。
- 正文里让每一段只承担一个推进任务：交代事实、解释变化、给出判断、补充影响。
- 多用具体产品动作、市场反应、用户体验差异承接观点，少用空泛行业黑话。
- 允许保留锋利判断，但别写成情绪宣泄；结尾优先落到“这意味着什么”。

### 口播稿

- 开头必须在 1 到 3 句内进主题；绕背景、先解释后落点，视为失败。
- 不能连续写出大段方案腔或过书面的长句；嘴里不顺，就重写。
- 少讲平台、体系、策略这类抽象词，多讲“发生了什么”“你为什么在意”。
- CTA 要像收住一条口播，不像流程提示页；批量改稿时，CTA 不能一条套一条。

### 社媒文案

- 开头优先是结论、反差、变化或一个有信息量的观察。
- 压缩修饰词，保留能撑住观点的关键信息。
- 少用“炸裂、封神、吓人、赢麻了”这类夸张词。
- 允许更快节奏，但不要为了抓人牺牲清楚度或把全文写成喊话。

### 品牌稿 / 产品稿

- 保留业务目的、卖点、转化目标和品牌定位。
- 把“赋能、闭环、全链路、价值锚点、行业领先”这类空词压掉，换成用户能感到的变化。
- 少自夸，多讲产品动作、使用场景、效果差异。
- 语气可以专业，但不要端着；需要保守时，走“克制但清楚”的方向。

## Hard Fail Conditions

- 命中任一项，当前稿件不得交付，必须重写。
- 任何一句里同时出现“不是”和“而是”，直接判失败，除非用户明确要求保留；“看的不是”“重点不是”“关键不是”“真正不是”都算同类。
- 出现“说白了”“一句话总结”“最狠的是”“值得一提的是”这类模板转折，直接判失败，除非用户明确要求保留。
- 编造事实、补案例、补数据、补采访，或把用户原有立场改偏。
- 文体写错：把口播、社媒、品牌稿都改成同一种科技评论腔。
- 口播稿出现明显不可读的大段书面句、方案腔、解释先行节奏。
- 批量改稿里多个 CTA 明显同构，只是换词复述。

## Review Gate

- 先完成改写，再按 Hard Fail Conditions 做一次明确复检。
- 复检先做字面扫描，再做文体扫描。第一步先逐句扫“不是”与“而是”是否同句共存，命中数必须为 0；再扫禁用词和 CTA 是否同构。
- 如果发现对比关系还在，先不要微调语气，直接改句型：拆成两句，或改成正向判断句。
- 只要命中任一硬错误，就重写对应部分，不得带着问题直接交付。
- 复检只做一轮，但这一轮必须真实执行，不能把自检写成口头安慰，也不能跳过扫描步骤。
- 原文已经成熟时只做轻改；不要为了显示能力而过改。

## Output Rule

- 最终只输出复检后的版本，不输出带缺陷的初稿。
- 默认直接给成稿，不额外教学；用户要求对比、多版本或理由时再补。
- 目标是像编辑做过手术，不像模型在“完成任务”。
